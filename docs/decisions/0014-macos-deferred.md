# 0014. macOS deferred until after 1.0

- **Status:** Accepted
- **Date:** 2026-10-03
- **Plan sections:** 2, 11.2, 13.5, 13.6, 14 (M0, M1, M7, M8), 15 (R-03, R-13), 16.2 ("macOS
  deferred until after 1.0"), Reference R1, R4

## Context

The maintainer decided on 3 October 2026 (plan 16.2) that Verdra 1.0 supports Windows (the main
platform) and Linux with Sober only. The reasons, from the plan:

- The maintainer has no Mac. macOS needs a paid Apple Developer account, and real Mac hardware
  for every Roblox test: Macs can't legally be virtualized on other hardware.
- macOS carries the plan's largest open risk, R-03 (the trust file on a code-signed Roblox).
- The two macOS runners doubled the CI queue, and the Intel runner missed the startup budget:
  the built app's window appeared after 2023 ms on `macos-15-intel` (budget 1500 ms, plan 12.4),
  against 497 ms on Windows, 967 ms on Linux and 993 ms on `macos-15` (run 37042513638 on
  `fd36abf`, 2 October 2026).

## Decision

- **Platforms for 1.0:** Windows and Linux with Sober. Nothing macOS-specific is built, tested,
  packaged or released until this decision is lifted. Plan 11.2, the macOS rows in 4.6, 9.1 and
  10.5, Reference R3 and the macOS parts of specs stay as reference only.
- **Code:** `soil/humus.py` defines the Platform protocol and an `Unsupported` result (system and
  reason, no text; the UI turns it into M-PLAT-01). meadow (Windows), orchard (macOS) and tundra
  (Linux) each provide one `PLATFORM`. orchard's `PLATFORM.support()` and the `support()` of each
  orchard module return `Unsupported(system="macos", reason="deferred")`, so the protocol keeps
  three implementations and macOS can return without restructuring. Nothing outside `soil/`
  checks the operating system: the tray's macOS branches are gone and the startup Activity line
  (M-SHELL-05) names the system through the Platform. `tests/soil/test_humus.py` checks both.
- **CI:** `ci.yml` and `nightly.yml` run on `windows-latest` and `ubuntu-24.04` only, with every
  gate kept. Decision record 0009 (the `macos-15` label) no longer applies.
- **Dependencies:** the cryptography cap below 49 for Intel macOS (decision record 0007) is
  removed; uv.lock moves to cryptography 50.0.2 everywhere. uv locks only for Windows and Linux
  (`environments` and `required-environments`), so a missing macOS wheel can no longer block an
  update; macholib, a macOS-only PyInstaller dependency, leaves the lockfile.
- **Packaging:** no DMG and no macOS build. The macOS app icon, tray template images and their
  sizes are still generated by `tools/icons.py` (cheap, no testing needed).
- **Risks:** R-03 is inactive; R-13 covers Windows signing only. No Apple Developer Program.
- **The Intel-macOS startup finding** (2023 ms against the 1500 ms budget) is closed as not
  applicable: no Intel Mac is supported now, and Intel Macs are dropped when macOS returns.

## Consequences

- One CI run needs two runners per job instead of four; the queue roughly halves.
- The M0 exit gate and every later real-machine check cover Windows and Linux (the Linux checks
  run in a virtual machine on the maintainer's Windows PC).
- Lifting the deferral needs: a Mac with Apple silicon for testing, the Apple Developer Program,
  and a new decision record. Intel Macs are then dropped. That record restores the macOS runner
  (Apple silicon only), the macOS lock targets, and real orchard modules.
